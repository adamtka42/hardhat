# Setting up a QRL Hardhat project

A QRL Hardhat project is any directory with a valid `hardhat.config.js` file.
The config file defines your networks, paths, tasks, and Hyperion compiler
settings.

This guide explains the normal project layout, the built-in sample project, and
the files QRL Hardhat expects.

## Creating a project

Install QRL Hardhat in a new npm project:

~~~sh
mkdir qrl-hardhat-project
cd qrl-hardhat-project
npm init --yes
npm install --save-dev @theqrl/hardhat
~~~

Run QRL Hardhat in a directory without a config file to start the project
creation prompt:

~~~sh
npx hardhat
~~~

The prompt offers:

- `Create a sample project`
- `Create an empty hardhat.config.js`
- `Quit`

Choose the sample project when you want working contracts, tests, scripts, and
network config. Choose the empty config when you want to build the structure
yourself.

## Empty config

The empty project option creates:

~~~js
module.exports = {};
~~~

This is enough for QRL Hardhat to recognize the directory as a project, but it
does not configure accounts or QRL networks. Add a `networks` section before
running tests or deployments that need a provider.

## Sample project

The sample project creates this structure:

~~~text
contracts/
  Sample.hyp
scripts/
  sample-script.js
test/
  sample-test.js
hardhat.config.js
.gitignore
.gitattributes
~~~

The prompt asks whether to add `.gitignore` and `.gitattributes`.

`.gitignore` excludes generated and local files such as `artifacts/`, `cache/`,
and dependency directories.

`.gitattributes` adds:

~~~text
*.hyp linguist-language=Hyperion
~~~

This helps GitHub display `.hyp` files as Hyperion.

## Project directories

The default project layout is:

- `contracts/`: Hyperion source files using the `.hyp` extension.
- `test/`: Mocha tests that use the Hardhat Runtime Environment.
- `scripts/`: deployment, maintenance, and smoke-test scripts.
- `artifacts/`: generated compiled contract artifacts.
- `cache/`: generated compiler cache and console history.

`artifacts/` and `cache/` are generated by QRL Hardhat and should normally stay
out of commits.

## Sample contract

The generated `contracts/Sample.hyp` contract stores and reads a single
`uint256` value:

~~~solidity
// SPDX-License-Identifier: MIT
pragma hyperion >=0.0;

contract Sample {
    uint256 private value;

    event ValueChanged(uint256 newValue);

    function store(uint256 newValue) public {
        value = newValue;
        emit ValueChanged(newValue);
    }

    function retrieve() public view returns (uint256) {
        return value;
    }
}
~~~

Compile it with:

~~~sh
npx hardhat compile
~~~

For compile details, see [Compiling contracts](compile-contracts.md).

## Sample config

The generated `hardhat.config.js` includes:

- an `accounts` task that prints `qrl_accounts`,
- a `qrlLocal` network for in-process tests,
- a `qrl` HTTP network for go-qrl endpoints,
- `QRLJS_MONOREPO_PATH` for loading qrlLocal VM packages,
- `QRL_RPC_URL` and `QRL_ACCOUNT_SEED` for HTTP networks.

`qrlLocal` is the default network in the sample project. The relevant config fragment looks like this:

~~~js
module.exports = {
  defaultNetwork: process.env.HARDHAT_DEFAULT_NETWORK || "qrlLocal",
  networks: {
    qrl: {
      url: process.env.QRL_RPC_URL || "http://127.0.0.1:33462",
      accounts,
    },
    qrlLocal: {
      type: "qrl-local",
      chainId: 1,
      qrlJsMonorepoPath: process.env.QRLJS_MONOREPO_PATH,
      from: localAccountAddress,
      accounts: [{ address: localAccountAddress, balance: "1000000000000" }],
      blockGasLimit: 30000000,
    },
  },
};
~~~

For the full config reference, see [Configuration](../config/README.md).

## Running the sample project

Build `qrljs-monorepo`, set `QRLJS_MONOREPO_PATH`, and run:

~~~sh
QRLJS_MONOREPO_PATH=/path/to/qrljs-monorepo \
npx hardhat test --network qrlLocal
~~~

Run the sample script on qrlLocal:

~~~sh
QRLJS_MONOREPO_PATH=/path/to/qrljs-monorepo \
npx hardhat run scripts/sample-script.js --network qrlLocal
~~~

Run it against an HTTP go-qrl network:

~~~sh
QRL_RPC_URL=http://127.0.0.1:33462 \
QRL_ACCOUNT_SEED=<qrl-extended-seed> \
npx hardhat run scripts/sample-script.js --network qrl
~~~

Do not commit real QRL extended seeds. Keep them in environment variables or
local secret management.

## Adding contracts, tests, and scripts

Add new `.hyp` contracts under `contracts/`, then compile:

~~~sh
npx hardhat compile
~~~

Add tests under `test/`:

~~~js
const assert = require("assert");

describe("Sample", function () {
  it("deploys and calls a contract", async function () {
    this.timeout(300000);

    const Sample = await qrl.getContractFactory("Sample");
    const sample = await Sample.deploy();

    const tx = await sample.store(42);
    await tx.wait();

    const stored = await sample.retrieve();
    assert.strictEqual(stored.toString(10), "42");
  });
});
~~~

Add scripts under `scripts/` when you need repeatable deployment or maintenance
actions. See [Writing scripts](scripts.md).

## Choosing a network

Use `qrlLocal` for fast local tests that do not need a running node:

~~~sh
npx hardhat test --network qrlLocal
~~~

Use an HTTP network when you need to interact with go-qrl:

~~~sh
npx hardhat test --network qrl
~~~

Private networks launched by Docker or Kurtosis often expose dynamic ports. Set
`QRL_RPC_URL` instead of committing a machine-specific port.

For qrlLocal details, see [qrlLocal](../qrl-local/README.md). For deployment
details, see [Deploying contracts](deploying.md).
