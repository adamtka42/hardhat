# Hardhat Runtime Environment

The Hardhat Runtime Environment, or HRE, is the object QRL Hardhat creates for
every task, test, and script. It contains the resolved config, selected network,
provider, task runner, and QRL-specific runtime helpers.

In this fork, the HRE is QRL-only. It does not expose Ethereum convenience
libraries such as Ethers.js, Web3.js, Waffle, or Truffle by default. Contract
interaction goes through `hre.qrl` and direct `qrl_*` JSON-RPC calls.

## What the HRE contains

The runtime object has these core fields:

- `config`: the resolved Hardhat config, including `networks`, `paths`, and
  `hyperion`.
- `hardhatArguments`: parsed global CLI arguments such as `--network`,
  `--config`, `--verbose`, and `--show-stack-traces`.
- `tasks`: the task definitions loaded from QRL Hardhat, the project config, and
  plugins.
- `run(taskName, taskArgs?)`: executes another task programmatically.
- `network`: the selected network object.
- `qrl`: QRL runtime helpers for artifacts, deployment, calls, transactions, and
  contract wrappers.

The `network` object contains:

- `network.name`: the selected network name.
- `network.config`: the resolved network config.
- `network.provider`: the QRL provider used to send `qrl_*` JSON-RPC requests.

## Accessing the HRE

When a task runs, the HRE is passed as the second argument to the task action:

~~~js
task("accounts", "Prints QRL accounts").setAction(async (_, hre) => {
  const accounts = await hre.network.provider.send("qrl_accounts");
  for (const account of accounts) {
    console.log(account);
  }
});
~~~

QRL Hardhat also injects the HRE fields into the global scope while tasks,
tests, and scripts are running. This is why tests and scripts can use `network`
or `qrl` directly:

~~~js
const [from] = await network.provider.send("qrl_accounts");
const Sample = await qrl.getContractFactory("Sample");
~~~

If you prefer explicit imports, require the package:

~~~js
const hre = require("@theqrl/hardhat");

async function main() {
  const [from] = await hre.network.provider.send("qrl_accounts");
  console.log(from);
}
~~~

## Provider access

Use `hre.network.provider.send(method, params?)` for direct RPC access. QRL
Hardhat speaks QRL JSON-RPC methods, for example:

~~~js
const chainId = await hre.network.provider.send("qrl_chainId");
const accounts = await hre.network.provider.send("qrl_accounts");
const balance = await hre.network.provider.send("qrl_getBalance", [
  accounts[0],
  "latest",
]);
~~~

Prefer `qrl_*` methods. Legacy `eth_*` compatibility is not the primary surface
of this fork.

For HTTP networks, the provider points at the configured go-qrl endpoint. For
`qrlLocal`, it points at the in-process QRL VM provider loaded from a built
`qrljs-monorepo` checkout.

## QRL helpers

`hre.qrl` is the main high-level runtime API for contracts and QRL
transactions.

### Artifacts

~~~js
const artifact = await hre.qrl.readArtifact("Sample");
console.log(artifact.contractName);
console.log(artifact.abi);
~~~

Artifacts are generated by the Hyperion compile task and loaded from
`config.paths.artifacts`.

### Deploying contracts

Use a factory for the common deployment path:

~~~js
const [from] = await hre.network.provider.send("qrl_accounts");
const Sample = await hre.qrl.getContractFactory("Sample");
const deployment = await Sample.deploy({ from }, [42], {
  timeoutMs: 300000,
});

console.log(deployment.hash);
console.log(deployment.address);
~~~

The second argument can be constructor arguments or pre-encoded constructor data.
`deploy` sends the transaction, waits for a receipt, checks that deployment did
not fail, and returns the normalized QRL contract address.

You can also deploy through the lower-level helper:

~~~js
const deployment = await hre.qrl.deployContract(
  "Sample",
  { from, gas: 15000000 },
  [42],
  { timeoutMs: 300000 }
);
~~~

### Attaching to contracts

~~~js
const sample = await hre.qrl.getContractAt("Sample", deployment.address);
~~~

Factories also support `attach`:

~~~js
const sample = Sample.attach(deployment.address);
~~~

### Sending transactions

`qrl.sendTransaction` sends a transaction object with `qrl_sendTransaction`:

~~~js
const txHash = await hre.qrl.sendTransaction({
  from,
  to: sample.address,
  data: sample.encodeFunctionData("store", [42]),
});

await hre.qrl.waitForTransaction(txHash, 300000);
~~~

Transaction quantity fields such as `gas`, `gasLimit`, `gasPrice`, `value`,
`nonce`, `chainId`, `maxFeePerGas`, and `maxPriorityFeePerGas` can be numbers,
hex strings, or decimal strings. QRL Hardhat normalizes them before sending RPC
requests.

### Simulating calls

`qrl.call` sends a `qrl_call`. The default block tag is `latest`:

~~~js
const result = await hre.qrl.call({
  from,
  to: sample.address,
  data: sample.encodeFunctionData("retrieve"),
});
~~~

Use `callStatic` on contract wrappers for ABI decoding:

~~~js
const [stored] = await sample.callStatic.retrieve({ from });
console.log(stored.toString(10));
~~~

`callStatic` simulates execution. It must not persist state changes.

## Contract wrappers

A contract returned by `getContractAt` or `factory.attach` has these fields.
`factory.deploy` returns a deployment result with the transaction hash, receipt,
and deployed address; call `getContractAt` or `attach` when you need a contract
wrapper.

- `address`: normalized QRL contract address.
- `contractName`: artifact contract name.
- `artifact`: the loaded artifact.
- `functions`: sends state-changing functions and calls read-only functions.
- `send`: always sends a transaction and returns the transaction hash.
- `callStatic`: simulates a call and decodes the return values.

Example:

~~~js
await sample.functions.store(42, { from, gas: 15000000 });
const [stored] = await sample.callStatic.retrieve({ from });
const txHash = await sample.send.store(43, { from });
await hre.qrl.waitForTransaction(txHash);
~~~

The low-level methods are also available:

~~~js
const data = sample.encodeFunctionData("store", [44]);
const txHash = await sample.sendTransaction(data, { from });
const rawResult = await sample.call(sample.encodeFunctionData("retrieve"));
const decoded = sample.decodeFunctionResult("retrieve", rawResult);
~~~

`decodeEventLog(eventName, log)` decodes one log, and
`decodeReceiptLogs(receipt)` decodes matching logs from a receipt.

## Overloaded functions

When an ABI contains overloaded functions, use the full canonical signature:

~~~js
await resolver.functions["setAddr(bytes32,address)"](node, recipient, {
  from,
});

const [resolved] = await resolver.callStatic["addr(bytes32)"](node);
const data = resolver.encodeFunctionData("setAddr(bytes32,address)", [
  node,
  recipient,
]);
~~~

QRL Hardhat also exposes the short function name when the name is unambiguous:

~~~js
const [name] = await token.callStatic.name();
~~~

For overloaded names, ambiguous short names are intentionally not added to the
function maps. Use `name(type1,type2)` to avoid silently selecting the wrong ABI
fragment.

## Waiting for receipts

`waitForTransaction(hash, timeoutMs?, pollIntervalMs?)` polls
`qrl_getTransactionReceipt` until a receipt is available or the timeout expires:

~~~js
const receipt = await hre.qrl.waitForTransaction(txHash, 300000, 1000);
~~~

The default timeout is `120000` ms and the default poll interval is `1000` ms.
Private networks can be slow, so integration tests often pass a larger timeout.

## Running other tasks

Use `hre.run` to invoke another task from a task, script, or test:

~~~js
await hre.run("compile");
~~~

This is useful in standalone scripts that import `@theqrl/hardhat` directly and
need to make sure artifacts are current before deploying.

## Differences from upstream Buidler docs

Older upstream Buidler documentation refers to the BRE, Buidler EVM, Solidity,
Ethers.js, Web3.js, Waffle, Truffle, Ganache, Ethereum HD wallets, and
`@nomiclabs/buidler`. Those examples are not valid QRL Hardhat examples.

Use these QRL-specific surfaces instead:

- `@theqrl/hardhat` instead of `@nomiclabs/buidler`.
- `hardhat.config.js` instead of `buidler.config.js`.
- Hyperion `.hyp` contracts instead of Solidity `.sol` contracts.
- `qrlLocal` instead of `buidlerevm` or the old Ethereum `hardhat` network.
- QRL addresses and QRL extended seeds instead of Ethereum addresses and private
  keys.
- `hre.qrl` and `qrl_*` JSON-RPC methods instead of Ethers/Web3 helpers.
