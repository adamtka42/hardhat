# QRL Hardhat project skeleton

If you want to get started with a QRL contract project quickly, use the project
created in this tutorial as a small skeleton. It contains the same pieces that a
larger project will normally use: contracts, tests, scripts, and network
configuration.

## What's included

- The Hyperion `Token` contract used in this tutorial
- A test suite using `hre.qrl` and Mocha
- A deployment script that works with qrlLocal and HTTP go-qrl networks
- A `hardhat.config.js` file with qrlLocal and HTTP network examples

### Hyperion contract and tests

In the root of the project you have the QRL Hardhat project we put together
through this tutorial with the `Token` contract. To refresh your memory on what
it implements:

- There is a fixed total supply of tokens that cannot be changed.
- The entire supply is assigned to the address that deploys the contract.
- Anyone can receive tokens.
- Anyone with enough tokens can transfer tokens.
- The token is non-divisible. You can transfer 1, 2, 3, or 37 tokens but not
  2.5.

### Project architecture

- `contracts/` contains Hyperion `.hyp` contracts.
- `test/` contains Mocha tests.
- `scripts/` contains deployment and maintenance scripts.
- `hardhat.config.js` configures tasks, qrlLocal, and HTTP networks.
- `artifacts/` and `cache/` are generated by the compile task.

## How to use it

First install dependencies:

```sh
npm install
```

Compile the contracts:

```sh
npx hardhat compile
```

Run the tests on qrlLocal:

```sh
npx hardhat test --network qrlLocal
```

Deploy to qrlLocal:

```sh
npx hardhat run scripts/deploy.js --network qrlLocal
```

Deploy to an HTTP go-qrl network:

```sh
QRL_RPC_URL=http://127.0.0.1:33462 \
QRL_ACCOUNT_SEED=<qrl-extended-seed> \
npx hardhat run scripts/deploy.js --network qrl
```

This skeleton is intentionally small. You can replace `Token.hyp` with your own
contracts, add more tests, and add scripts for deployment, verification, or
maintenance tasks.
